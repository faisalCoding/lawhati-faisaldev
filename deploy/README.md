# نشر خادم المزامنة على سيرفر kayanalnhda.sa

يعمل خادم المزامنة على السيرفر نفسه الذي عليه الموقع (Hostinger VPS بنظام Ubuntu وخادم Apache)، ويتصل به التطبيق على العنوان:

```
wss://faisaldev.site/lawhati-sync/
```

## ما الذي يتغير على السيرفر

- ملف واحد: `/opt/lawhati-faisaldev/lawhati-faisaldev.cjs`.
- خدمة systemd اسمها `lawhati-faisaldev`:
  - تعمل على `127.0.0.1:8788` فقط، فلا تصل إليها الشبكة الخارجية مباشرة.
  - تحفظ البيانات في `/var/lib/lawhati-faisaldev/`: اللوحات المشتركة في `data.json`، وأجهزة إشعارات الفريق في `devices.json`.
  - تعيد التشغيل تلقائيًا بعد أي توقف أو إعادة تشغيل للسيرفر.
- في Apache: تفعيل وحدتي `proxy` و `proxy_http`، وملف إعداد `lawhati-faisaldev-sync.conf` يمرّر المسار `/lawhati-sync/` وحده إلى الخدمة. لا يتغير شيء آخر في موقع Laravel.

تحتاج الخدمة Node.js 18 أو أحدث مثبتًا على مستوى النظام. على Ubuntu 24.04 يكفي:

```bash
sudo apt install -y nodejs
```

## النشر التلقائي (من هذا الجهاز عبر SSH)

```bash
SSH_TARGET=root@72.61.207.108 npm run deploy:server
```

السكربت يعمل بالترتيب التالي:
1. يبني الخادم في ملف واحد ويرفعه إلى السيرفر.
2. ينسخ البيانات احتياطيًا قبل أي تغيير: مجلد `/var/lib/lawhati-faisaldev` كاملًا إلى `/var/backups/lawhati-sync/<التاريخ والوقت>`، ويعدّ اللوحات المشتركة فيه.
3. يثبّت الخدمة ويشغّلها.
4. يفعّل مسار Apache، بعد أن يختبر إعدادات Apache. إذا رُفضت الإعدادات يتراجع عن التغيير تلقائيًا.
5. يتحقق من أن كل شيء يعمل، ومن أن الخادم بعد إعادة تشغيله حمّل عدد اللوحات نفسه الذي كان قبلها. إن اختلف العدد يتوقف ويطبع مكان النسخة الاحتياطية.

تشغيله مرة أخرى يحدّث الخادم دون فقدان البيانات: التحديث يستبدل البرنامج وحده، ولا يكتب في ملفات البيانات. والنسخ الاحتياطية لا تُحذف تلقائيًا.

- إن وجد الخادم عند تشغيله ملف بيانات لا يُقرأ (تالفًا أو ناقصًا)، يرفض العمل ويترك الملف كما هو، بدل أن يبدأ فارغًا ويكتب فوقه. عندها استرجع آخر نسخة احتياطية:

```bash
ssh root@72.61.207.108 'ls /var/backups/lawhati-sync/'
ssh root@72.61.207.108 'cp -a /var/backups/lawhati-sync/<النسخة>/. /var/lib/lawhati-faisaldev/ && systemctl restart lawhati-faisaldev'
```


## إشعارات الفريق

حين يعدّل أحد بطاقة يتابعها زميل له، يرسل الخادم إشعارًا لهاتف الزميل **مباشرة إلى Web Push Cloud Messaging**، بمفتاح حساب خدمة يبقى على هذا السيرفر، دون أي وسيط.

**وضع المفتاح (مرة واحدة):** نزّل المفتاح من Web Push (إعدادات المشروع ← Service accounts ← Generate new private key)، ثم من جهازك:

```bash
ssh root@72.61.207.108 'install -d -m 700 /etc/credstore'
```

```bash
scp ~/Downloads/اسم-ملف-المفتاح.json root@72.61.207.108:/etc/credstore/lawhati-faisaldev-vapid.json
```

```bash
ssh root@72.61.207.108 'chmod 600 /etc/credstore/lawhati-faisaldev-vapid.json && systemctl restart lawhati-faisaldev && journalctl -u lawhati-faisaldev -n 5 --no-pager'
```

يجب أن يظهر في السجل: `Team notifications: sending through Web Push project sa-kayanalnhda-lawhati`.

- لا يقرأ المفتاح غير root. يسلّمه systemd للخدمة وحدها (`ImportCredential=` في ملف الخدمة، ويحتاج systemd 254 أو أحدث، وهو المتاح في Ubuntu 24.04).
- دون المفتاح تعمل المزامنة كالمعتاد، ويطبع السجل أن إشعارات الفريق متوقفة.
- في `devices.json` لكل هاتف: معرّف عشوائي سري، ورمز Web Push، والاسم الذي يظهر لفريقه، والبطاقات التي يتابعها.
- التعديلات المتتالية خلال دقيقة تصل في إشعار واحد. ويمكن تغيير المدة بالمتغير `TEAM_BATCH_MS` (بالملّي ثانية) في ملف الخدمة.
- لا يصل الإشعار لصاحب التعديل، ولا لمن يفتح اللوحة نفسها في تلك اللحظة.
- إذا حُذف التطبيق من هاتف، يرفض Web Push رمزه، فيحذفه الخادم ويتوقف عن الإرسال إليه.

تحديث الخادم بعد هذه الإضافة يكون بأمر النشر نفسه، والنسخ الأقدم من التطبيق تستمر في العمل معه.

## المستخدمون (موظفو لوحة الإدارة)

إسناد البطاقات يعتمد على واجهة جديدة في موقع النهضة (`/api/lawhati/me` و `/api/lawhati/team`) وزر «رمز لوحتي» في نافذة الموظفين. لذلك يُنشر موقع النهضة بهذه الإضافة أولًا، ثم خادم المزامنة، ثم نسخة الويب.

- لا تحتاج الإضافة ترحيلات، ولا تغيّر أي جدول. رموز الدخول تُحفظ في جدول `personal_access_tokens` الموجود أصلًا، باسم `lawhati`.
- يتحقق خادم المزامنة من رمز كل هاتف بسؤال `LAWHATI_API` (في ملف الخدمة: `https://faisaldev.site/api/lawhati`). يحفظ رقم الموظف واسمه في `devices.json`، ولا يحفظ الرمز.
- قبل نشر موقع النهضة يظهر للموظف عند الدخول: «تعذّر الوصول إلى لوحة الإدارة». لا يتأثر شيء آخر.

## نسخة الويب من التطبيق

تُنشر على السيرفر نفسه في `https://faisaldev.site/lawhati/`، بجوار لوحة إدارة موقع النهضة:

```bash
SSH_TARGET=root@72.61.207.108 npm run deploy:web
```

السكربت يعمل بالترتيب التالي:
1. يبني نسخة الويب في `dist-web/` (`npm run build:web`).
2. يرفعها إلى `/var/www/lawhati` دفعة واحدة: يفكّها بجوار النسخة الحالية ثم يبدّلهما، فلا يرى الزوار موقعًا نصف منسوخ.
3. يفعّل ملف `lawhati.conf` في Apache، وهو يربط المسار `/lawhati` بالمجلد وحده، ويعيد أي عنوان داخله (مثل رابط لوحة) إلى صفحة التطبيق. يُختبر الإعداد قبل التفعيل، ويُتراجع عنه تلقائيًا إذا رُفض.
4. يتحقق من أن الصفحة ورابطًا داخليًا يفتحان التطبيق، ومن تحويل العنوان القديم، ومن صفحة التسليم.

### الانتقال من العنوان القديم

كان العنوان `https://faisaldev.site/lawhati/`، وصار يحوّل إلى العنوان الجديد مع بقية المسار (رابط لوحة أو بطاقة يبقى صالحًا).

المتصفح يحفظ اللوحات غير المشتركة لكل عنوان على حدة، فلا يراها العنوان الجديد تلقائيًا. لذلك:
- في أول زيارة للعنوان الجديد، يفتح التطبيق في الخلفية صفحة صغيرة على العنوان القديم (`/lawhati/migrate.html`، ولا تُحوَّل). تسلّمه هذه الصفحة نسخة مما حفظه المتصفح هناك.
- تُضاف اللوحات غير الموجودة في العنوان الجديد، ولا يُستبدل شيء موجود فيه.
- لا يُحذف شيء من العنوان القديم، فتبقى نسخته هناك احتياطًا.
- لا يسمح Apache بفتح صفحة التسليم إلا من داخل العنوان الجديد (`frame-ancestors`)، وهي لا ترسل النسخة إلا إليه.
- اللوحات المشتركة محفوظة في الخادم أصلًا، فتبقى كما هي.
- من أضاف التطبيق إلى الشاشة الرئيسية من العنوان القديم يضيفه مرة أخرى من الجديد.

- لا يتغير شيء في موقع Laravel: جرّبت الإعداد على Apache مع موقع يعيد كل مسار مجهول إلى `index.php`، فبقيت مسارات الموقع كما هي.
- ملفات البرمجة والخطوط تُخزَّن في المتصفح طويلًا، لأن أسماءها تتغير مع كل بناء، وصفحة التطبيق تُفحص في كل زيارة. لذلك تصل النسخ الجديدة فورًا.
- تحتاج وحدتي `headers` و `rewrite` في Apache، والسكربت يفعّلهما.
- التحقق يدويًا:

```bash
curl -sI https://faisaldev.site/lawhati/
curl -sI https://faisaldev.site/lawhati/
```

- الإلغاء:

```bash
ssh root@72.61.207.108 'a2disconf lawhati && systemctl reload apache2 && rm -rf /var/www/lawhati'
```

## الصيانة

متابعة السجلات:

```bash
sudo journalctl -u lawhati-faisaldev -f
```

إعادة تشغيل الخدمة:

```bash
sudo systemctl restart lawhati-faisaldev
```

إلغاء كل شيء:

```bash
sudo a2disconf lawhati-faisaldev-sync && sudo systemctl reload apache2 && sudo systemctl disable --now lawhati-faisaldev
```

## الحماية المضمّنة

- لا يستطيع الجهاز تعديل لوحة إلا بعد الانضمام إليها برمزها.
- تُحظر محاولات تخمين الرموز بعد 30 محاولة فاشلة من العنوان نفسه خلال 10 دقائق.
- لكل عنوان حد أقصى 20 اتصالًا، ولكل اتصال حد لعدد الرسائل.
- حجم اللوحة الواحدة محدود بـ 2 ميغابايت، وعدد اللوحات الإجمالي بـ 5000.
- لا يستطيع الجهاز متابعة بطاقات لوحة لم ينضم إليها، فلا تصله أخبار لوحات لا يملك رمزها.

لا يوجد تسجيل دخول للمستخدمين. من يملك رمز اللوحة يستطيع الوصول إليها، فشارك الرموز مع فريقك فقط.
