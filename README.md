# لوحتي — نسخة faisaldev.site

تطبيق مبسّط لإدارة المهام بأسلوب **كانبان**، مبني بـ React Native و Expo، وواجهته عربية من اليمين إلى اليسار.

هذه **نسخة مستقلّة تمامًا** من المشروع، لا بديلًا عن نسخة لوحة الشركة. تختلف عنها في شيء واحد جوهري: **الحسابات مفتوحة للتسجيل**.

## الحسابات

لا يُنشئ أحدٌ حسابك نيابةً عنك ولا يُرسل إليك رمزًا:

1. سجّل في <https://faisaldev.site/apps/lawhati/signup>
2. افتح التطبيق وادخل بنفس البريد وكلمة السرّ — لا رمز ولا خطوة ثانية
3. في التطبيق: الإعدادات ← الدخول، والصق الرمز

الموقع يحفظ بصمة الرمز لا الرمز نفسه، فلا يستطيع عرضه ثانيةً. ضياعه لا يكلّف شيئًا: أنشئ غيره، وأوقف القديم من الصفحة نفسها إن ضاع معه جهاز.

خادم المزامنة لا يحفظ حسابات: يأخذ الرمز المميّز الذي يقدّمه الجهاز، ويسأل `faisaldev.site/api/lawhati/me` عن صاحبه، ويحتفظ بالاسم والرقم دقائق معدودة.

### إسناد البطاقات

نسخة الشركة تعرض قائمة الموظفين لإسناد البطاقات إليهم. هنا المسجَّلون غرباء بعضهم عن بعض، وعرض قائمتهم يكشف اسم كل مسجِّل لكل مسجِّل آخر — فقائمة «الفريق» هنا **صاحب الحساب وحده**.

الإسناد عبر لوحة مشتركة يحتاج معرفة أعضاء اللوحة، وهي عند خادم المزامنة لا عند الموقع. حتى يسأله الموقع، لا يُسمّى أحدٌ لأحد.

## التشغيل محليًا

```bash
npm install
npm run server      # خادم المزامنة
npx expo start      # التطبيق
```

## نسختان على خادم واحد

هذه النسخة ونسخة الشركة تعملان على الجهاز نفسه. كلّ ما يمكن أن يتصادم بينهما **مفصول**:

| | نسخة الشركة | هذه النسخة |
| --- | --- | --- |
| الخدمة | `kanban-sync` | `lawhati-faisaldev` |
| المنفذ | `8787` | `8788` |
| التثبيت | `/opt/kanban-sync` | `/opt/lawhati-faisaldev` |
| البيانات | `/var/lib/kanban-sync` | `/var/lib/lawhati-faisaldev` |
| مسار المزامنة | `/kanban-sync/` | `/lawhati-sync/` |
| إعداد أباتشي | `kanban-sync.conf` | `lawhati-faisaldev-sync.conf` |
| اعتماد Firebase | `kanban-sync-fcm.json` | `lawhati-faisaldev-fcm.json` |

وإعداد أباتشي لهذه النسخة **مقيَّد بمضيفها** (`faisaldev.site`)، لأن إعداد الشركة عامّ بلا قيد وكان سيلتقط طلبات هذا الموقع أيضًا.

## الإشعارات — من خادمك وحده

لا فايربيس ولا حساب عند أحد. الخادم يوقّع كل إشعار بمفتاح **VAPID** يملكه ويشفّره لمشترِكه وحده، ويسلّمه إلى نقطة المتصفّح التي لا تستطيع قراءته.

**توليد المفاتيح — مرّة واحدة:**

```bash
npm run vapid
```

ضع الناتج على الخادم في `/etc/credstore/lawhati-faisaldev-vapid.json` بصلاحية `600` لـroot، ثم `systemctl restart lawhati-faisaldev`. تبديل المفاتيح لاحقاً **يُبطل كل الاشتراكات**، فولّدها مرّة واحتفظ بها.

بلا مفاتيح يعمل كل شيء عدا إشعارات الفريق.

### ما يصل ومتى

| الحالة | يصل؟ |
|---|---|
| المتصفّح مفتوح أو التطبيق مثبَّت على الشاشة الرئيسية | ✅ إشعار نظام |
| التطبيق الأصلي مفتوح | ✅ عبر اتصال المزامنة |
| تذكير موعد | ✅ محلي على الجهاز، بلا خادم |
| **التطبيق الأصلي مُغلَق تماماً** | ❌ |

الأخيرة قيد المنصّة لا اختيار تصميم: إيقاظ تطبيق أندرويد مُغلَق يمرّ عبر خدمات جوجل حتماً، وهذه النسخة لا تستعملها. ومن ثبّت نسخة الويب على شاشته الرئيسية حصل على السلوك نفسه بلا ذلك.

## النشر

